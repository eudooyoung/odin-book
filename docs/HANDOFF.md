## 현재 진행 상황

사용자가 `docs/PLAN.md`를 직접 작성하며 검토·수정해 왔다. **기능 요구사항의 첫 번째 초안은 대체로 정리된 상태**다.

현재 `PLAN.md` 구성:
- `0. Overview`: X 또는 Threads와 유사한 간단한 텍스트 기반 SNS
- `1. Common Rules`: 비로그인 사용자는 로그인·회원가입 페이지만 접근할 수 있고, 로그인 사용자는 모든 프로필과 게시글을 열람할 수 있음
- `2. Functional Requirements`: Authentication, Profile, User Discovery, Follow, Post, Feed, Like, Comment

**User Discovery에는 사용자 목록에서 팔로우 요청을 보낼 수 있다는 요구사항이 이미 추가되었다.** 이후 검토에서 누락으로 다시 지적하지 말 것.

## 문서 작성 방향과 결정 근거

초기에는 Entity별 CRUD에 맞춰 요구사항을 정리하려 했지만, 사용자 기능과 데이터 조작 관점이 섞여 분류가 불명확해졌다. 이에 기존 구조를 버리고 **사용자가 무엇을 할 수 있는가**를 중심으로 다시 작성했다.

합의한 원칙:
1. **Overview:** 만들 서비스의 성격과 목표를 설명한다.
2. **Common Rules:** 여러 기능에 공통 적용되는 규칙을 정의한다. 개요와 분리하고 기능 요구사항보다 앞에 둔다. 뒤에 나오는 기능을 해석할 때 전제가 되기 때문이다.
3. **Functional Requirements:** 사용자 관점의 기능을 영역별로 정의한다. 특정 기능에만 적용되는 조건은 해당 기능과 함께 다룬다.
4. 여러 화면에서 같은 데이터를 표시한다고 해서 곧바로 중복 요구사항인 것은 아니다. 같은 동작을 불필요하게 반복 정의하는 것은 피한다.
5. 기능을 억지로 CRUD에 대응시키지 않는다. Entity 구조, API, 데이터베이스, OAuth 세부 구현은 이 단계에서 미리 정하지 않는다.
6. 문서는 가볍게 유지한다. 사용자가 영어로 직접 작성하고 AI가 간결하게 검토하는 방식으로 진행한다.

현재 제목 번호가 `0`부터 시작하는 것은 사용자가 작성한 형식이다. 별도 논의 없이 번호만 바꾸지 말 것.

## 합의된 서비스 동작

- **접근 권한:** 비로그인 상태에서는 로그인·회원가입 페이지만 접근 가능. 로그인 사용자는 팔로우 여부와 관계없이 모든 사용자의 프로필과 게시글을 열람할 수 있다. 비공개 프로필 기능은 현재 범위에 없다.
- **인증:** 이메일/비밀번호 로그인 및 소셜 로그인. 현재 PLAN에는 X, Threads, Instagram이 명시되어 있다. 인증 라이브러리는 학습 목적으로 Passport.js를 선호하지만, 제공자별 OAuth 구현 가능성·계정 연동 정책 등은 미확정이다. **계정 생성과 동시에 기본 프로필을 자동 생성한다.**
- **프로필과 식별자:** `displayName`(화면 표시 이름)과 고유 공개 식별자인 `handle`(UI 표기: **Profile ID**)을 구분한다. 둘 다 수정할 수 있다. 프로필은 이름, Profile ID, 사진, 자기소개, 작성 게시글, 팔로워·팔로잉 수 및 목록을 표시한다. 다른 사용자의 프로필에서는 현재 사용자와의 팔로우 상태를 표시한다. **프로필 사진 업로드·변경은 이번 프로젝트의 필수 범위**로 결정했다. 기본 프로필 이미지도 제공한다.
- **사용자 탐색:** 전체 사용자 목록, Display Name·Profile ID 검색, 프로필 이동, 사용자 목록에서 팔로우 요청 보내기를 지원한다.
- **팔로우:** 즉시 팔로우가 아닌 **요청·승인 방식**. 요청 전송·조회·취소, 받은 요청 조회·수락·거절, 언팔로우를 지원한다.
- **게시글:** 텍스트 전용, 최대 500자. 조회·작성 및 작성자 본인의 수정·삭제. 게시글에 내용·작성자·좋아요·댓글을 표시한다.
- **피드:** 홈 피드에는 본인과 **내가 팔로우하는 사용자**의 게시글을 최신순으로 표시한다. 모든 사용자의 게시글을 모으는 Explore 피드는 원안 필수 요구사항이 아니므로 현재 범위에서 제외했다.
- **좋아요와 댓글:** 게시글 좋아요·취소 및 좋아요 수 표시. 게시글 댓글 조회·작성·수정·삭제를 지원한다. 대댓글과 댓글 좋아요는 보류했다.

## 아직 결정하지 않은 사항

- **계정 삭제와 비활성화:** 현재 PLAN의 `delete(deactive)`는 서로 다른 개념을 함께 쓰고 있다. `deactive`도 적절한 동사가 아니며, 비활성화의 동사는 `deactivate`다. 정책부터 결정해야 한다.
- 회원가입 필수 입력 정보, 최초 Display Name·Profile ID 생성 규칙, Profile ID 변경에 따른 URL 처리
- 소셜 계정 연결·인증 제공자별 차이·세션 방식
- 팔로우 중복 요청, 거절 후 재요청, 관계 상태 및 권한
- 회원 탈퇴나 게시글 삭제 시 연관 댓글·좋아요·팔로우 관계 처리
- 게시글·댓글의 세부 입력 검증, 이미지 업로드 형식·용량·저장 방식, 페이지네이션, 오류 처리
- **배포:** Odin Book 과제의 필수 요구사항이다. 사용자 기능 명세에 억지로 넣지 않고 후속 개발·배포 계획에서 다루기로 했다.

## 협업 방식

- 사용자가 `PLAN.md`를 직접 작성한다. **명시적인 수정 요청이 없으면 PLAN을 편집하지 말 것.**

- 사용자의 의견에 기계적으로 동의하지 말고, 판단 근거와 대안을 제시한다.

- 영어 문장에 대한 피드백은 짧게 한글로 제공한다.
- 기능 요구사항·공통 규칙·개별 비즈니스 규칙·기술 설계를 혼동하지 않는다.
